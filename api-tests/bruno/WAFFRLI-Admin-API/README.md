# WAFFRLI-Admin-API (Bruno)

Platform administration API: `/api/v1/admin/*` (guard `admin`, Sanctum bearer token).
It covers all 45 admin routes: authentication, settings, currencies, cities, delivery areas,
delivery fee rules (including the fee quote), customer accounts, password reset, and negative and authorization tests.

The Filament panel (`/admin`) uses a separate session guard (`admin_web`) and is not an API.

```
WAFFRLI-Admin-API/
├── environments/Local.bru        base_url http://localhost:8080 (Docker Compose stack)
├── environments/Shared-Dev.bru   base_url of a shared dev server (edit locally)
├── .env.example                  WAFFRLI_ADMIN_EMAIL / WAFFRLI_ADMIN_PASSWORD (copy to .env, git-ignored)
└── 01 Authentication … 09 Authorization and Negative Tests
```

## Run

1. Create a local admin, if you don't have one. The command prompts for the password, which is never stored:

   ```bash
   docker compose exec app php artisan waffrli:create-super-admin
   ```

2. Copy `.env.example` to `.env` in this folder and fill in that admin's email and password.

3. Run the collection:

   ```bash
   cd api-tests/bruno/WAFFRLI-Admin-API
   bru run --env Local
   ```

`Authentication / Login (success)` captures `admin_token` at runtime only; it is never written to disk.

## What it changes

Each run creates one setting, currency, city, delivery area and fee rule, all with random unique names or codes.
The API has no delete route by design, so the collection **deactivates** each record at the end of its folder.

`Customer Accounts` deactivates and then re-activates the last listed customer, so it is reversible.

Run it only against a local or shared **development** database, never production.

## Notes

- The paginated lists of delivery areas and fee rules return their items under `deliveryareas` and `deliveryfeerules`.
  This is the starter `BasicCrudService` contract (lower-cased model name); `/all` returns `delivery_areas` and `delivery_fee_rules`.
  It is kept for compatibility.
- The password-reset and login-challenge negatives are throttled. Running the collection several times a minute can return 429, which the tests accept.

The `.bru` files are generated by `api-tests/bruno/generators/admin.py`: edit the generator, not the files.

Verified (2026-11-05) on the Docker Compose stack with Bruno CLI 2.15.1: 69 requests and 221 tests, all passing.
